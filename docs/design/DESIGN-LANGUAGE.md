# FCF-Laboratory Design Language

## Controlled criticality

FCF-Laboratory should feel like a drop of uranium beauty inside a precision machine: quiet on the surface, unusually dense with capability underneath.

The interface is not decorative minimalism. It is **operational minimalism**.

## Visual principles

- The current work owns the visual field.
- Empty space is protected, not treated as unfinished space.
- Permanent controls are exceptional.
- Panels appear on demand and disappear cleanly.
- Prefer native system materials and typography over custom chrome.
- Use borders only when spatial grouping cannot be communicated more elegantly.
- Motion communicates state; it never performs for the user.
- One restrained accent may indicate energy, execution, selection, or important state.
- Avoid neon programmer aesthetics, dashboard density, ornamental telemetry, and visual noise.
- Light and dark appearances must both feel intentionally designed.

## Interaction principles

- Opening a project must expose useful content before indexing finishes.
- Tools should be summonable from commands, context, keyboard, or object actions rather than permanently occupying screen space.
- Tabs represent open technical objects, not application modes.
- A single open object may hide the tab strip entirely.
- The navigator, inspector, terminal, Git, AI, and engine surfaces are revealable rather than mandatory.
- Context-sensitive commands should understand the selected object.

## Mac character

The macOS application should feel at home beside first-party Apple desktop software while retaining a distinct FCF identity.

Use native menus, keyboard conventions, windows, sheets, popovers, accessibility, drag and drop, file handling, typography, materials, and platform behavior. Do not imitate macOS with custom web-like controls.

## Aesthetic test

Before keeping a visible element, ask:

1. Does it help the user think, navigate, or understand state?
2. Does it need to be permanently visible?
3. Is this the quietest correct representation?
4. Does it remain beautiful at rest?

If the answer to the first question is no, remove it. If the answer to the second is no, make it summonable.
