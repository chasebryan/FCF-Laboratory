# Contributing to FCF-Laboratory

FCF-Laboratory values structural discipline, native quality, performance, and visual restraint.

Before adding a feature:

1. Identify the subsystem that owns it.
2. Keep platform-specific presentation out of portable core logic.
3. Prefer existing protocols and standards before inventing a new one.
4. Avoid new permanent interface chrome unless it is demonstrably necessary.
5. Keep expensive work off the interactive thread.
6. Add or update an ADR when a change alters a foundational architectural rule.
7. Put files in the narrowest correct directory; do not use the repository root as a convenience location.

A feature is not complete merely because it works. It must also be organized, responsive, and visually coherent with the rest of the Laboratory.
